Removes an attribute whose value the schema would have had anyway, leaving a file that means exactly the same.

A schema shows indexed="true" the same way whether deleting it would change the index or nothing at all. The difference is not in the file: it depends on what the field's <fieldType> declares, on the class that type names, and on the version the schema's own root element states. Attributes that carry no weight are dimmed, and this removes the one under the caret.

The same holds inside an analyzer, where the answer comes from one place rather than three. A <filter>, <tokenizer> or <charFilter> inherits nothing, so ignoreCase="false" on a stop filter is removable exactly when false is the default that factory's own code falls back to.

It is offered rather than applied because restating a default is correct Solr, and often deliberate — writing indexed="true" can be a way of recording that the question was considered. Nothing here treats the attribute as a mistake; the plugin reports only that removing it changes nothing.

Never offered where the value cannot be determined. A default that depends on the field type is resolved only when the catalog carries the class that type names — for a custom class it does not, and an attribute that might be load-bearing is left alone rather than dimmed on a guess. A factory attribute is judged only where the default was read out of that factory's own code; one Solr computes at runtime, and one on a class outside the catalog, are left alone.
