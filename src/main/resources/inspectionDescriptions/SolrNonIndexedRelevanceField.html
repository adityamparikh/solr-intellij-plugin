Reports a query-field parameter in solrconfig.xml that names a field the schema declares but does not index.

The field is there, spelled correctly, and the parameter still does nothing. A qf naming an indexed="false" field adds no clause to the query and no boost to the score, because its terms were never written to the inverted index for the query parser to match against. Solr does not complain, the handler still answers, and results are ranked by everything except the field the author meant to emphasise.

Four parameters are examined: qf, pf, pf2 and pf3. Those are the ones whose values become term and phrase queries against the index. bf and boost are left alone on purpose — their values are function queries, read per document from doc values rather than from the index, so boosting on a non-indexed field there is correct and common.

indexed is resolved rather than read: from the field, then from its field type, then from Solr's own default for the schema version and the type's class. Where that resolution cannot reach an answer — a field type naming a class this build has never seen — nothing is reported.

Example: <str name="qf">title^3 body</str> where the schema declares <field name="body" type="text_general" indexed="false" stored="true"/>.
